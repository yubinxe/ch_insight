# 청약인사이트 — 소비자 디자인·전환 퍼널 최종 지침

2026-09-14 / 사용자의 타깃 정정과 디자인 요구를 반영한 최신 기준

## 1. 이번 제품의 본질

이 사이트의 주인공은 청약·임대 기회를 찾는 일반 소비자다. 사업자는 소비자의 조건·관심공고·알림 선택·지원 준비 이력을 내부 CRM으로 축적하고 활용한다. 소비자에게 CRM 운영도구를 판매하거나 담당자 중심 서비스로 전환하지 않는다.

소비자가 느껴야 하는 순서:

> 보기 좋고 믿을 만하다 → 내게 맞는 공고가 궁금하다 → 생각보다 쉽게 찾았다 → 이 결과를 저장하고 싶다 → 새 공고도 알려주면 좋겠다 → 가입하자 → 다음에도 여기서 확인하자.

핵심은 시선을 붙잡고 다음 행동의 동기를 계속 제공하는 것이다. 매 단계마다 큰 선택 하나만 제시한다. 공포 문구·가짜 마감·근거 없는 실시간 인원 대신 개인에게 실제로 유용한 변화로 다시 방문할 이유를 만든다. 사용자가 원하는 결과를 빠르게 얻는 방문도 성공이다.

## 2. 디자인 콘셉트: ‘내 집 기회를 발견하는 개인화 서비스’

키워드: 선명함, 여유, 친근함, 정확함, 기대감.

첫 방문에서는 큰 한글 타이틀과 실제 결과 미리보기로 매력을 만든다. 공고를 읽을 때는 금액·지역·마감이 정돈되어 신뢰를 준다. 저장·가입 과정에서는 상태 변화와 자연스러운 연결이 완성도를 만든다.

현재 화면의 명조 헤드라인, 14px 본문, 13px 메뉴, 11.5px 보조글, 작은 각진 요소와 업무용 용어는 소비자 전면에서 교체한다. 기존 데이터·로직은 필요한 부분을 재사용하되 공개 화면을 단순 색상 변경으로 끝내지 않는다.

‘수억원을 쓴 것 같은 완성도’의 판단 기준은 큰 로고나 복잡한 모션이 아니다. 글자·간격·카드·아이콘·실제 데이터·반응형·오류 상태가 하나의 기준으로 맞물려야 한다. 랜딩만 멋지고 결과가 낡은 관리자 표로 바뀌면 실패다.

## 3. 타이포그래피: 크게, 그러나 역할별로

설치된 GmarketSansTTFBold.ttf와 GmarketSansTTFMedium.ttf를 확인했다. Pretendard 파일도 확인했다. 권장 조합은 **Gmarket Sans Bold/Medium 제목 + Pretendard 본문·입력·버튼·상세정보**다.

Gmarket Sans는 브랜드 인상과 짧은 후킹 문구에 쓰고, 긴 설명·숫자가 많은 상세 UI는 Pretendard로 읽기 쉽게 유지한다. 모든 글자를 Gmarket Bold로 만들지 않는다. G마켓 공식 가이드도 Bold를 강조 메시지에 활용하고 정보 전달 UI의 과도한 사용을 지양한다. [공식 타이포그래피 가이드](https://gds.gmarket.co.kr/foundation/typography)

| 용도 | 데스크톱 | 모바일 | 글꼴·행간 |
|---|---:|---:|---|
| 홈 메인 타이틀 | 60px | 36px | Gmarket Bold, 1.23~1.28 |
| 홈 설명 | 20px | 17px | Pretendard 400~500, 1.65 |
| 섹션 제목 | 36px | 28px | Gmarket Medium, 1.35 |
| 결과 페이지 제목 | 32px | 26px | Pretendard 700, 1.4 |
| 공고 카드 제목 | 22px | 20px | Pretendard 650~700, 1.4 |
| 핵심 금액 | 26px | 24px | Pretendard 700, 1.25 |
| 일반 본문 | 17px | 16px | Pretendard 400~500, 1.6 |
| 메뉴·주요 버튼 | 16~18px | 16px | Pretendard 600 |
| 카드 보조정보 | 14px | 14px | Pretendard 400~500, 1.5 |
| 출처·부가설명 | 13px | 13px | Pretendard 400, 1.5 |

본문 16px 미만은 핵심 정보를 읽는 영역에 쓰지 않는다. 숫자는 자릿수 정렬을 유지한다. 한국어 제목은 단어 중간 줄바꿈을 피하고 -0.02em 정도의 절제된 자간으로 시작한다. 320px 화면에서 넘치면 타이틀만 32px까지 완화한다. 설명·입력을 작게 줄여 해결하지 않는다.

컴퓨터에 설치된 폰트만 지정하면 방문자에게 같은 글꼴이 보장되지 않는다. 프로젝트에 배포 가능한 파일과 라이선스를 포함하고 웹에서 제공한다. 공식 배포조건을 확인한 후 필요한 굵기만 사용한다. Next.js 로컬 폰트 사용법은 설치된 버전 문서로 확인한다. [공식 서체 배포 페이지](https://news.gmarket.com/fonts/)

아이콘은 동일한 선 두께·24px 계열을 사용한다. 이모지를 기능 아이콘처럼 혼용하지 않는다. 실제 사진이 있으면 동일 비율로 정리하고, 없으면 차분한 지역·주거 유형 그래픽을 쓴다. AI로 만든 건물 이미지를 실제 단지 사진처럼 쓰지 않는다.

## 5. 홈: 첫 화면부터 소비자가 자기 결과를 상상하게 한다

### 헤더

청약인사이트 / 공고 찾기 / 청약 가이드 / 관심공고 / 로그인.

주 버튼은 ‘내 기회 찾기’. 고객관리·물건관리·종합현황·운영시연 버튼은 공개 헤더에서 제거한다. 관리자 기능은 인증된 별도 영역으로 이동한다. 공개 메뉴에서 링크만 숨기는 것으로 접근 제어를 대신하지 않는다.

### 첫 화면

작은 상단 문구: ‘청약부터 공공임대까지’

메인 제목:

> 내 조건에 맞는 집,
> 놓치지 않고 찾는 방법.

설명:

> 복잡한 공고를 하나씩 비교하지 않아도 괜찮아요.
> 내 조건에 맞는 후보를 찾고, 관심공고의 일정까지 챙겨보세요.

주 버튼: **내 조건으로 공고 찾기**

보조 링크: ‘모집 중인 공고 둘러보기’

버튼 아래: ‘가입 없이 먼저 확인하세요’. 실제 측정 전에는 ‘30초 완성’ 같은 소요시간을 확정하지 않는다.

데스크톱은 좌 52% 카피·CTA / 우 48% 결과 미리보기. 헤더 아래 여백은 64~80px. 우측은 브랜드 일러스트만 두지 말고 **결과 카드 1개 + 작은 일정 카드 1개**로 구성한다. 떠다니는 장식 카드는 최대 2개다.

미리보기는 ‘내 조건에 맞는 후보 / 예산 범위 내 / 소득·자산 확인 필요 / 관심공고 저장’을 읽을 수 있게 만든다. 가상 내용이면 ‘화면 예시’ 배지를 카드 안에 넣는다. 점수·공고 건수·D-day를 임의의 실제 성과로 표시하지 않는다.

모바일에서는 카피 → 주 CTA → 결과 미리보기 순서다. 첫 CTA를 눌러야 하는 이유가 390×844 화면에서 읽혀야 한다. 모바일 미리보기를 위해 CTA를 아래로 밀지 않는다.

### 첫 화면 아래

1. **지금 살펴볼 모집공고**: 지역·모집유형 칩과 카드 3개. 선택 시 실제 결과를 변경한다. 모두 보기로 공고 탐색 연결.
2. **복잡한 청약, 이 순서로 준비하세요**: 조건 확인 / 관심 저장 / 일정 확인의 짧은 3단계. 긴 사업소개 제거.
3. **새 공고를 매번 찾지 않아도 되도록**: 저장한 조건 → 새 후보 → 알림이라는 구체적인 편익과 ‘내 조건 저장하기’.
4. **확인하고 추천합니다**: 원문 링크·업데이트 시각·미확인 항목 예시. 실제 없는 제휴 로고·이용자 후기·수상 배지는 사용하지 않는다.
5. **처음이라 궁금한 질문**: 회원가입 필요 여부, 알림 내용, 추천과 공식 자격의 차이 등 4~5개.
6. 마지막 CTA: ‘내 조건에 맞는 공고부터 확인해보세요.’

긴 로드맵·운영 과정·CRM 설명·요금제는 첫 홈의 주인공이 아니다.

## 6. 분석: 입력하는 동안에도 다음을 보고 싶게

3단계는 지역 → 주거비 → 가구·선호조건으로 정리한다. 자격 판단에 필요한 세부정보는 결과 확인 후 필요한 시점에 받는다.

입력 영역은 최대 680px, 큰 제목 하나, 도움말 한 문장, 선택 카드와 다음 버튼으로 구성한다. ‘조건진단 실행’ 대신 ‘다음’, 마지막은 ‘내 후보 확인하기’로 쓴다. 선택 즉시 테두리·배경·체크 상태를 바꾸고 선택 내용이 상단에 남는다. 뒤로 가도 입력이 유지된다.

예산은 직접 숫자 입력과 슬라이더를 함께 제공한다. 단위는 만원으로 고정하고 큰 금액을 한글로 병기한다. ‘아직 정하지 않았어요’는 UNKNOWN으로 저장하며 임의 선호지역·연령·소득으로 바꾸지 않는다.

로딩은 짧고 실제 처리상태를 보여준다. 불필요하게 지연시켜 AI가 오래 생각하는 연출을 하지 않는다. 오류가 나도 입력을 보존한다.

## 7. 결과: 가입을 요구하기 전에 충분한 이득을 준다

상단 제목: ‘이 조건에서 먼저 살펴볼 공고예요’.

조건 요약 칩: 지역 / 보증금 / 월세 / 면적. 옆에 ‘조건 바꾸기’. 실제 데이터가 뒷받침하는 후보 건수만 표시한다.

카드 정보 순서:

1. 공급유형·접수 상태.
2. 큰 공고명.
3. 보증금·월세·면적.
4. 추천 이유 2개: 예산 차이와 지역 등 실제 값.
5. 자격 추가 확인 사항.
6. 공식 마감과 출처·확인시각.
7. ‘자세히 보기’ / 하트 ‘관심 저장’.

높은 매칭점수보다 실제 비용과 조건을 크게 보여준다. 데스크톱 2~3열, 모바일 1열. 카드 전체 클릭과 저장 버튼의 클릭을 분리한다. 서로 다른 제목 길이에서도 가격·버튼 위치를 정렬한다.

**가입 전 최소 1개 이상의 유의미한 후보 상세와 추천 이유를 볼 수 있어야 한다.** 모든 내용을 흐리게 가려 가입만 요구하는 구조로 만들지 않는다.

상세 안에서 원문·준비 항목·공식 일정이 연결된다. ‘이 공고 마감 알림 받기’가 자연스러운 다음 행동이다. 예산을 넘는 후보는 별도 영역에 정확한 초과금액과 함께 둔다.

## 8. 저장·알림·가입: 행동의 의도를 이어받는다

| 소비자의 행동 | 다음 화면 | 가입 후 도착점 |
|---|---|---|
| 관심 저장 | ‘이 공고를 저장해둘까요?’와 간편 가입 | 원래 공고 저장 완료 |
| 새 공고 알림 | ‘선택한 지역·예산의 새 공고를 알려드려요’ + 알림 선택 | 동일 조건 저장·설정된 알림 확인 |
| 마감 알림 | 해당 공고명·마감·채널 설명 | 해당 공고 알림 설정 완료 |
| 준비 일정 저장 | ‘준비 일정을 이어서 관리하세요’ | 동일 준비건·일정 화면 |

가입은 데스크톱 대화상자·모바일 하단 패널 또는 단독 간결 화면으로 구성한다. 핵심은 돌아갈 위치와 선택한 공고를 보존하는 것이다. 소셜 로그인은 실제 연결된 제공자만 보여준다. 이메일 등 대체 수단도 일관되게 설계한다. 연결 안 된 로그인 버튼을 작동하는 척 만들지 않는다.

알림 수신은 가입과 구분하여 명시적으로 선택하게 한다. 동의 범위·시각·채널을 저장한다. 브라우저 권한 팝업은 첫 방문 직후 띄우지 않고 사용자가 알림을 선택한 뒤 요청한다. 가입 취소 시 입력과 후보가 남아야 한다.

완료 문구: ‘관심공고에 저장했어요’ / ‘이 조건으로 새 공고를 확인할게요’. 즉시 관심공고 또는 내 기회 화면으로 연결한다. 가입을 마쳤는데 빈 홈으로 보내면 실패다.

## 9. 재방문: 방문할 때마다 바뀐 이유가 보인다

로그인 홈은 긴 소개 페이지를 반복하지 않는다. ‘새로 확인할 공고’, ‘관심공고의 일정’, ‘준비 중인 공고’를 중심으로 구성한다. 마지막 방문 이후 실제 변경분만 ‘새로’ 표시한다.

알림 클릭은 해당 공고나 변경된 일정으로 바로 연결한다. 종료된 공고라면 마감 사실과 저장조건에 맞는 다음 후보를 보여준다. 읽지 않은 알림 수를 늘리는 대신 관련성과 후속 행동을 측정한다.

관심 없음 이유는 ‘지역 / 비용 / 면적 / 시기’ 등 간단한 선택으로 받는다. 명시적으로 저장한 선호를 단순 클릭 한 번으로 덮어쓰지 않는다. 저장·비교·알림 선택이 반복될수록 소비자에게 의미 있는 CRM이 쌓인다.

## 10. 내부 CRM: 사업자가 직접 활용하는 데이터

저장할 핵심은 사용자 ID 또는 가입 전 세션 ID, 선택한 지역·예산·공급유형, 조회·저장·알림 신청·준비 시작, 조건 수정, 최근 방문, 수신 동의다. 가입 시 같은 사용자의 가입 전 탐색을 중복 없이 연결한다. 입력값의 생성 주체·확인시점을 보존한다.

운영자는 ‘동작구 관심 + 보증금 범위 + 관심 저장 + 알림 동의’ 같은 조합으로 세그먼트를 본다. 점수는 소비자에게 집을 배정하는 기준이 아니라 서비스 이용 관심을 이해하기 위한 내부 지표다. 알림 발송은 관심도와 별도로 동의 여부·채널·빈도를 확인한다.

초기 이벤트: home_view, analysis_started, analysis_completed, notice_viewed, save_clicked, signup_started, signup_completed, notice_saved, alert_opted_in, alert_delivered, alert_opened, preparation_started. 이벤트는 실제 성공 후 기록하고 중복 기준을 둔다. 개인정보를 분석 이벤트 문자열에 그대로 넣지 않는다.

보고할 퍼널은 방문 → 분석 시작 → 결과 → 저장/알림 의도 → 가입 완료 → 저장/알림 설정 완료 → 재방문이다. 데모 행동은 실사용 통계에서 제외한다. 체류시간은 보조지표이며 클릭만 늘고 유의미한 행동이 줄면 개선으로 보지 않는다.

## 11. Claude에게 줄 구현 순서

**1차: 소비자 화면의 인상을 바꾸는 작업**

README의 소비자 금지·명조 고정 지침 수정 → 소비자/운영 레이아웃 분리 → 폰트·타입·색·간격 공통 규격 → 공개 헤더 → 홈 전체 → 결과 카드·공고 상세. 현재 ‘시스템 소개 사이트’가 ‘내가 쓰는 서비스’로 보이게 한다.

**2차: 전환 동선을 실제 연결하는 작업**

조건 입력 → 결과 → 관심 저장·알림 → 가입 → 원래 선택 복원 → 내 관심공고. 공통 규격을 전 화면에 적용한다. 홈만 개편하고 나머지 화면은 작은 글자·관리자 표로 남겨두지 않는다.

**3차: 다시 방문할 이유와 운영자 CRM**

개인 홈·변경 알림·마감 일정 → 실제 행동 이벤트 → 운영자 세그먼트. 정정공고·실패·마감 상태도 같은 수준으로 디자인한다.

기존 정확성 지시서의 예산·면적·허위 날짜·당첨확률 문제는 관련 화면을 만드는 동안 함께 수정한다. 정확성 점검을 핑계로 소비자 디자인을 생략하거나 운영 도구를 먼저 확장하지 않는다.

## 12. ‘완성도 높음’의 수용 기준

- 1440px, 1024px, 768px, 390px, 360px 및 320px 폭에서 핵심 동선을 확인한다.
- 소비자 5명에게 첫 화면을 5초 보여준 뒤 서비스 목적과 누를 버튼을 설명하게 한다. 내부 목표는 4명 이상이 이해하는 것; 보장된 전환율이 아니다.
- 홈·결과·상세·가입·가입 후 화면에 같은 타이포그래피와 버튼 체계가 적용된다.
- 핵심 본문 16px 이상, 상호작용 영역 최소 44×44px를 지킨다. 입력 라벨은 항상 보인다.
- 일반 텍스트 대비 4.5:1을 목표로 검사하고 키보드 포커스·200% 확대·모션 감소 설정을 확인한다.
- 중요한 정보는 색상만으로 구분하지 않는다. 마감 배지와 미확인 배지에 텍스트가 있다.
- 버튼·카드는 150~220ms의 짧은 상태 전환만 사용한다. 스크롤 강제 이동·자동 반복 팝업은 넣지 않는다.
- 긴 공고명·큰 금액·원문 없음·후보 0건·로딩·오류·로그인 취소를 실제 화면으로 검증한다.
- 가입 후 원래 저장하려던 공고가 정확히 남는다. 같은 저장 요청으로 중복 기록이 생기지 않는다.
- 폰트 로딩 실패 시 대체 글꼴로도 레이아웃이 유지된다. 이미지·폰트 때문에 CTA가 뒤늦게 밀리지 않는다.
- 실제 측정값과 목표를 분리해 성능 결과를 보고한다. 모바일 첫 화면에 불필요한 지도·통계 차트를 로드하지 않는다.
- 최종 보고에는 주요 5개 화면의 데스크톱/모바일 비교와 작동한 퍼널, 남은 연결 사항을 제시한다.

## 13. Claude에 바로 붙여 넣을 시작 요청

이 프로젝트는 소비자를 위한 청약기회 서비스다. 소비자가 매력적인 화면에서 내 후보를 확인하고 관심 저장·알림 신청·회원가입·재방문으로 이어지게 만들어라. CRM은 내가 내부에서 활용한다. B2B나 담당자 중심 서비스로 바꾸지 마라.

docs/strategy/2026-09-14-consumer-design-direction.md를 최우선 디자인·퍼널 기준으로 읽고, 기존 implementation-brief의 정확성 조건을 함께 적용하라. README의 명조 고정·소비자 문체 금지·운영자 메뉴 노출 지침은 최신 사용자 요구에 맞게 수정하라.

Gmarket Sans 제목과 Pretendard 본문으로 전환하고, 본문 16~17px·모바일 헤드라인 36px·데스크톱 60px를 기준으로 정보 위계를 재설계하라. 홈뿐 아니라 결과·공고 상세·저장/알림 가입 화면·가입 후 관심공고까지 하나의 디자인 시스템으로 완성하라. 첫 화면에는 실제 결과를 상상할 수 있는 미리보기와 ‘내 조건으로 공고 찾기’를 배치하라. 결과를 먼저 보여주고 저장·알림 의도가 생긴 순간 가입을 연결하며, 가입 후 원래 선택을 복원하라.

소비자에게 보이는 실제 화면을 구현하고 모바일·데스크톱에서 검증하라. 색상·폰트만 바꾸거나 기획안만 출력하고 완료하지 마라. 실제 연결이 없는 알림·로그인·공고는 연결됐다고 표시하지 마라. 첫 결과물은 소비자 홈과 결과·상세의 완성된 시각적 흐름이며, 이어 가입과 관심 저장의 실제 동작까지 연결하라.
