## 슬라이드별 시나리오

### S1. 표지 — "청약, 감이 아니라 데이터로" (0:00–0:20)

> "여러분, 지난달 서울에서 나온 청약 공고가 몇 건이었는지 아시는 분 계신가요?"
> (2초 침묵)
> "저도 몰랐습니다. 청약홈에 다 있는데, 아무도 못 봅니다. 그래서 만들었습니다. **집캐치**입니다."

- **연출**: 질문 → 침묵 → 자백. 청중을 '모르는 편'에 세워 동질감을 만든다.
- 절대 하지 말 것: "안녕하세요, 저희 팀은…" 으로 시작하는 자기소개 오프닝. 첫 20초는 문제에만 쓴다.

### S2. 문제 정의 — 정보는 공개돼 있는데, 쓸 수가 없다 (0:20–1:20)

> "청약 정보는 **이미 100% 공개 데이터**입니다. 문제는 접근성이 아니라 **해석 가능성**입니다."

3대 병목:
1. **파편화** — 분양정보·경쟁률·당첨가점·지역통계가 각기 다른 API, 다른 화면에 흩어져 있다.
2. **비가독성** — 원본은 `SUBSCRPT_AREA_CODE`, `LWET_SCORE` 같은 코드값 테이블이다. 실수요자가 읽을 형태가 아니다.
3. **판단 공백** — 가장 중요한 질문("내 가점으로 여기 되나?")에 답해주는 곳이 없다. 커뮤니티 카더라가 그 자리를 채운다.

> "정보 비대칭이 아니라 **해석 비대칭**입니다. 이게 집캐치가 공격하는 지점입니다."

### S3. 타깃 — 첫 집을 노리는 2030 무주택자 (1:20–1:50)

- 페르소나: 28세, 수도권 거주, 청약통장 7년차, 가점 60점 초반. 공고는 보지만 **지원 여부를 못 정한다.**
- 핵심 인사이트: 이들이 원하는 건 매물 리스트가 아니라 **"내 위치"** 다. 등수를 알고 싶어 한다.

> "리스트를 더 주는 서비스는 많습니다. 집캐치는 **좌표**를 줍니다."

### S4. 솔루션 — 5개 질문, 한 화면 (1:50–2:30)

| 탭 | 답하는 질문 |
|---|---|
| 분양정보 | 지금 넣을 수 있는 게 뭐지? |
| 경쟁률 현황 | 이 단지, 얼마나 몰리지? |
| 핫플레이스 | 어느 지역이 과열됐지? |
| 당첨자 통계 | 실제로 누가 됐지? |
| AI 당첨 예측 | **나는 될까?** |

> "탭 5개는 기능 5개가 아니라, 실수요자의 **의사결정 5단계**입니다. 마지막 탭이 이 서비스의 존재 이유입니다."

### S5. 기능 ① 분양정보 — 놓치지 않게 만드는 D-day (2:30–2:55)

- 히어로 캐러셀 + KPI 4종(접수중 / 마감임박 / 총 공급세대 / 갱신시각).
- **마감임박 = 접수 종료 D-5 이내** 로 정의(`CLOSING_SOON_DAYS = 5`), KPI 클릭 시 해당 목록이 패널로 즉시 펼쳐진다.

> "청약에서 가장 비싼 실수는 떨어지는 게 아니라 **모르고 지나치는 것**입니다. 그래서 마감임박을 KPI 최상단에 올렸습니다."

### S6. 기능 ② 경쟁률 — 평균이 아니라 분포 (2:55–3:20)

- 지역별 평균 경쟁률 + 단지별 상세(공고번호 기준) + **특별공급/일반공급 분리**.
- 말할 포인트: 특공과 일반은 모수도 자격도 다르다. 합산 평균은 실수요자를 오도한다.

### S7. 기능 ③ 핫플레이스 — 전국 과열 지도 (3:20–3:50)

- 시·도 SVG 경계 기반 히트맵. 경쟁률을 색 강도로, 개별 단지를 마커로 배치. 줌·팬, 마커 호버 툴팁, 모바일 Bottom Sheet.
- **기술 자랑 포인트 1개만**: "좌표 데이터가 없는 공공 API라서, 지역 코드 → 시·도 bbox → 단지 마커 좌표를 **자체 레이아웃 알고리즘**으로 생성했습니다."

### S8. 기능 ④ 당첨자 통계 — 소문을 숫자로 (3:50–4:15)

- 연령별·지역별 신청자 대비 당첨자, 가점 분포(평균/최저/최고/중위).
- > "'요즘 60점으론 안 된다'는 말, 여기서 **월 단위로 검증**됩니다."

### S9. 기능 ⑤ AI 당첨 예측 — 이 서비스의 심장 (4:15–5:00)

- 3단계 입력(무주택 기간 → 부양가족 → 청약통장) → 가점 84점 체계로 환산 → **지역별 최근 당첨 가점 분포와 비교** → 확률(5~94%) + 3단 해석(가능성 높음 / 평균 / 보완 권장).
- 법적 근거 명시: 가점 총 84점 = 무주택기간 32 + 부양가족 35 + 입주자저축 가입기간 17 (「주택공급에 관한 규칙」 별표1).
- **정직하게 말할 것**: "블랙박스 예측이 아닙니다. 커트라인 대비 내 위치를 계산해 **근거 문장으로 되돌려주는** 규칙 기반 모델입니다. 그래서 왜 그 숫자인지 설명할 수 있습니다."

> 심사위원이 가장 좋아하는 문장: "우리는 맞히는 게 아니라 **설명 가능한 기준선**을 제공합니다."

### S10. 아키텍처 — 키는 서버에, 캐시는 엣지에 (5:00–5:30)

- Next.js 16 App Router / React 19 / TypeScript / Tailwind v4 / Recharts.
- 공공 API 키는 **서버 라우트(`app/api/*`)에만** 존재 — 클라이언트 노출 0.
- `revalidate` 기반 캐싱(경쟁률 600초 / 분양정보 300초)으로 공공 API 호출량과 응답 지연을 동시에 억제.
- 탭 전체 `dynamic import` + `ssr: false` → 초기 번들 최소화.

### S11. 라이브 데모 (5:30–8:30) — **3분, 클릭 7번**

| # | 동작 | 말할 한 줄 |
|---|---|---|
| 1 | 메인 진입 | "지금 이 숫자는 실시간 공공데이터입니다." |
| 2 | 마감임박 KPI 클릭 | "D-5 이내만 걸러집니다." |
| 3 | 단지 하나 클릭 | "공고 원문 대신, 필요한 것만." |
| 4 | 경쟁률 탭 | "특공과 일반을 분리해서 봅니다." |
| 5 | 핫플레이스 탭 → 수도권 줌 | "과열이 어디로 이동하는지 보입니다." |
| 6 | AI 예측 탭 → 7년/2명/9년 입력 | "이게 제 조건입니다. 64점." |

- **데모 안전장치**: 로딩 3초 넘어가면 말로 채우지 말고 곧바로 녹화본으로 전환한다("네트워크가 느리네요, 녹화본으로 보시죠" — 1초 안에 결정).

## Q&A 대비 (예상 질문 · 30초 답변)

**Q1. AI라고 했는데 사실 규칙 기반 아닌가요?**
> "맞습니다. 현재는 통계 기준선 대비 상대 위치를 계산하는 결정론적 모델입니다. 데이터가 누적되기 전에 학습 모델을 붙이면 설명력이 사라집니다. **설명 가능성을 먼저, 학습은 데이터가 쌓인 뒤** 가 저희 순서입니다."

**Q2. 예측이 틀리면 책임은?**
> "확률은 참고 지표이며 당락을 보증하지 않는다는 고지를 결과 화면에 유지합니다. 저희가 보증하는 건 확률이 아니라 **인용한 통계의 출처와 기준월**입니다."

**Q3. 청약홈이 같은 기능을 내놓으면?**
> "공공은 원천 데이터 제공이 미션이고, 개인화 판단은 기관 리스크가 커서 보수적입니다. 그 틈이 저희 자리입니다. 그리고 진입장벽은 기능이 아니라 **누적 사용자 가점 분포 데이터**에서 생깁니다."

**Q4. 수익 모델은?**
> "1단계 무료 확장 → 2단계 관심단지 알림·정밀 리포트 구독 → 3단계 시행사·분양대행사 대상 **수요 분석 B2B 데이터**. 마지막 단계가 실제 매출 축입니다."

**Q5. 데이터 신뢰도는?**
> "전량 공공데이터포털 청약홈 OpenAPI와 한국부동산원 통계입니다. 화면에 **기준월과 표본 수**를 함께 노출해 검증 가능하게 만들었습니다."

## 발표 전달 원칙 (리허설 체크)

1. **숫자는 하나씩만** — 한 슬라이드에 강조 숫자 1개. 두 개면 둘 다 안 남는다.
2. **기능이 아니라 질문을 말한다** — "히트맵이 있습니다"(✕) / "어디가 과열됐는지 3초에 압니다"(◎).
3. **약점은 선제 공개** — 로드맵 Q1의 가점 정합화가 그 장치다.
4. **침묵을 쓴다** — 핵심 문장 뒤 1.5초. 채우려 들면 밀도가 떨어진다.
5. **마지막 문장은 외운다** — 클로징만큼은 슬라이드를 보지 않는다.
